# Clustering Benchmark

Benchmarks two alternative clusterings against the existing pipeline on the
original 1291-row dataset (`final_two_smiles_with_modulus.csv`, pooled Morgan
count fingerprints), and on the extended `_add` dataset (1303 rows).

## Motivation

The existing pipeline projects the fingerprints with PCA-64, embeds them with
UMAP-2D, and runs KMeans(k=6) on the 2D coordinates (`unsupervised.py`).
UMAP is not distance-preserving, so clustering on the 2D embedding is
geometrically weakly founded. Two alternative labelings are benchmarked:

1. **pca64_kmeans** — KMeans(k=6) directly in the PCA-64 space (true,
   un-distorted distances). Recommended replacement: most stable partition
   (bootstrap ARI 0.95), k=6 is silhouette-optimal in this space.
2. **hdbscan_umap2d** — HDBSCAN on the existing UMAP-2D coordinates
   (min_cluster_size=50), the literal "UMAP then density clustering" option.
   Reference method only: its best cluster coincides with the existing best
   cluster (same embedding, so not an independent check).

Findings (original data, `results/comparison_table.csv`):

- The fingerprint space has weak, quasi-continuous cluster structure:
  silhouette ~0.27 in PCA-64 and flat over k=4..8; density clustering on
  PCA-64 marks most points as noise (not included in this benchmark).
- The one robust island is the best cluster (~68 rows, high prob_SR /
  prob_YM): identical under every method, so the downstream candidate
  materials are stable.
- `07_check_targets.py` replays the candidate-set construction (best cluster
  -> material pairs) and reports that pca64_kmeans keeps 9/10 of the
  LLM-screened formulas (F6 Starch+GelMA drops out); hdbscan_umap2d keeps
  10/10 (same best-cluster row set as the existing pipeline).

## Pipeline

| Script | Purpose |
|---|---|
| `common.py` | Shared loaders; rebuilds the existing labels from `clusters/cluster_0..5.csv` |
| `01_pca64_kmeans.py` | KMeans(k=6) in PCA-64 + silhouette-vs-k sweep |
| `02_hdbscan_umap2d.py` | HDBSCAN on `umap2d.npy`, min_cluster_size sweep {25,50,100} |
| `03_evaluate.py` | Full metric suite vs the existing labeling: internal metrics, ARI/NMI/AMI, bootstrap + seed stability, per-cluster prob_SR/prob_YM, Kruskal-Wallis |
| `04_prepare_add.py` | Rebuilds the `_add` dataset fingerprints from `clusters_add/` (needs rdkit) |
| `05_benchmark_add.py` | Both methods on the `_add` dataset |
| `06_evaluate_add.py` | Metric suite + cross-dataset consistency + best-cluster identity |
| `07_check_targets.py` | Are the 10 LLM-screened formulas still inside the clustering-then-combination candidate set? |

Run order: `01 -> 02 -> 03` (original), `04 -> 05 -> 06` (extended),
`07` (target check). Outputs go to `results/` and `results_add/`.

## Requirements

sklearn >= 1.3 (HDBSCAN), umap-learn, scipy, pandas, matplotlib;
`04_prepare_add.py` additionally needs rdkit. Everything runs single-threaded
and finishes in minutes for n ~ 1300.

## Notes

- `results_add/AB_concat1024_add.npy` (5 MB) is a derived copy regenerated by
  `04_prepare_add.py` and is not committed.
- Seeds fixed at 42 throughout; UMAP coordinates are reused from
  `../umap2d.npy` (original) / `results_add/umap2d_add.npy` (extended).
